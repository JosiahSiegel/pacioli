# scanner/mappings/ — generated, NOT a source of truth

The mapping-pack YAML files in this directory are **build-time copies**
of the canonical source-of-truth files under `mappings/` at the repo
root. They are placed here so the wheel install ships them inside the
`scanner` package, where `scanner/paths.py:resolve_mapping()`'s
`importlib.resources.files("scanner").joinpath("mappings/...")`
fallback can locate them at runtime.

## How they are produced

```bash
make sync-mappings
```

This target runs the helper script at `scripts/sync_mappings.py`,
which copies every `mappings/*.yaml` to `scanner/mappings/*.yaml` using
a byte-identical copy. The copy is deterministic and runs on every
`make install` (the install target depends on `sync-mappings`).

## How to add or modify a mapping pack

1. Edit (or add) `mappings/<framework>_<version>.yaml` at the repo root.
2. Run `make sync-mappings` to mirror it into this directory.
3. Commit only the `mappings/` change. The mirror under this
   directory is regenerated by the build and MUST NOT be committed
   (it is git-ignored via `scanner/mappings/*.yaml`).

## Why not just rely on the repo-root copy?

The repo-root `mappings/` directory is not a Python package, so
`[tool.setuptools.package-data]` cannot ship it inside the wheel.
The wheel install only includes files inside the `scanner` package
(or other declared packages), so a literal copy under
`scanner/mappings/` is the simplest way to satisfy both:

- the import-time default at `scanner/paths.py:78-79`
  (`<install-root>/mappings/pci_dss_4.0.1.yaml` for editable installs)
- the wheel-time fallback at `scanner/paths.py:97-103`
  (`importlib.resources.files("scanner").joinpath(...)`).

See `docs/ARCHITECTURE.md` and `docs/MAPPING_SCHEMA.md` for the
broader design context.
